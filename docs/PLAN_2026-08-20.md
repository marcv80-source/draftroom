# Build plan, 2026-08-20 (19 days to the draft)

Two tracks running in parallel. This file is the **contract** between them: the frontend codes
against the shapes below, the backend implements them. Neither track waits for the other.

Decisions taken by Marc, 2026-08-20:

- **Default projection = equal-weight blend of all three source families.** The target is an
  *amended composite*: weight every source, then **throw out the numbers we have challenged**.
  Equal-weight blend ships first; the challenge signals (below) feed the rejection rule after.
- **All four challenge mechanisms in scope:** team-envelope validator, personal tilt/override
  file, TD-regression flag, scout for a 4th independent source. Plus an agent sweep for
  *other* ways to challenge projections, each judged on merit before it ships.
- **Both tracks in parallel.**

## Why the projection work matters (measured, not asserted)

`build_real_board()` sets every player's PPG from **Sleeper's stat line alone**
(`backend/draftroom/validate/board.py:176`). ESPN and FantasyPros are fully resolved and
scored, but they only feed the `DISAGREE` badge. The point estimate driving every
recommendation ignores two of the three sources.

Measured 2026-08-20 on the cached board:

| Measure | Value |
|---|---|
| Ranked players with all 3 sources resolved | 185 of 189 |
| Players with >= 2 sources | 186 |
| Move > 5 spots when blending vs Sleeper-only | 87 |
| Move > 12 spots | 34 |
| Move > 24 spots | 4 |
| Top-60-by-ADP mean \|Sleeper − 3-source mean\| | 11.2 season pts |
| Same, max | 33.4 season pts |

Rank moves are on a proxy ordering (league-scored season points across the whole ranked pool),
not the final draft-value ordering. Treat magnitudes as indicative; the direction is not
ambiguous. Sleeper is the systematic low outlier on established backs and receivers
(Josh Jacobs 186 / 241 / 231; Rashee Rice 185 / 223 / 225 for Sleeper / ESPN / FantasyPros).

Note also: `CLAUDE.md` claims ESPN is the "Source of record for projections." The code uses
Sleeper. The doc and the implementation disagree. Resolved by this plan: neither is the source
of record, the **composite** is, and the active source is explicit in the payload and on screen.

## Track B: Rankings

### B1. Multi-source composite (the core)

**Blend component stats, then score once.** Not the reverse. `CLAUDE.md` is explicit: "Every
source adapter emits component stats, never fantasy points. Points are computed only by
applying the league's own Yahoo `stat_modifiers`." Blending points would also break the
per-game yardage bonus model, which needs yardage, not points.

New module: `backend/draftroom/valuation/composite.py`

```python
def blend_statlines(
    by_source: Mapping[str, StatLine | None],
    *,
    weights: Mapping[str, float] | None = None,   # None -> equal weight
    rejected: Container[tuple[str, str]] = (),    # (source, stat) pairs to exclude
) -> tuple[StatLine, BlendProvenance]
```

Rules, each of which is a correctness trap if got wrong:

- **Per stat, average only over sources that HAVE that stat.** `rec_tgt` comes from ESPN alone
  (FantasyPros publishes no targets column, Sleeper has none under any field name). A missing
  stat must never be averaged in as a zero. `BlendProvenance` records, per stat, how many
  sources contributed.
- **`games` is unknown, not zero, when a source omits it.** FantasyPros emits no games figure
  at all by design (`prep/manual_csv.py:512`) and `StatLine.games` stays `0.0` meaning
  "unknown". Blend `games` over sources reporting `> 0`; if none do, emit `0.0` so
  `PlayerSeason.expected_games=None` and the positional availability prior applies. Never
  average a 0.0 in as a real projection of zero games played.
- **`rejected` is the hook for the amended composite.** A `(source, stat)` pair listed there is
  dropped from that stat's average. The challenge mechanisms below populate it. Rejection is
  per source *and* per stat, not per player, because a source is usually wrong about one thing
  (a receiver's targets) while fine about the rest.
- **Everything stays visible.** `BlendProvenance` carries contributing sources, per-stat counts,
  and what was rejected and why. Nothing about how a number was reached may be hidden.

`build_real_board()` gains `source: str = "blend"`. Valid keys: `"blend"`, `"sleeper"`,
`"espn"`, `"fantasypros"`. A single-source key uses that source's statline unmodified, which is
what makes the toggle an honest comparison rather than a re-weighting.

Boards are 1.8s to build, so cache all four at server startup and switch instantly.

**Log the switch.** New event `source_changed` with payload `{"key": str}`. The record must show
which board a pick was made against, or the post-draft audit is guesswork.

### B3. Team-envelope validator

The check nobody's public ranking does properly: **do the slices add up to the pie?**

Sum every projection by NFL team and compare to a realistic team total: targets, rush attempts,
pass attempts, pass yards, rushing yards, total TDs. A real offense throws roughly 550-600
targets a year. If a team's projections sum to 700, at least one player there is wrong, and the
shape of the overage usually says which.

`backend/draftroom/valuation/envelope.py` + `tools/check_envelopes.py`. Output is a report, per
team and per source: the sum, the plausible band, the violation size, and the players
contributing most of the overage. **Per source** is the point: the source that busts the
envelope is the one to reject for that stat, which is exactly what `rejected` consumes in B1.

Envelope bands must be **fitted from `nflreadpy` history**, not invented. Two seasons of cached
weekly data are already in `data/raw/nflreadpy_weekly/`. State the fitted band and its years.

### B4. TD-regression flag

Touchdowns are the noisiest line in any projection. Flag players whose projected TD rate is an
outlier against their own projected yardage and usage, fitted on the same history. A flag, not
an adjustment, until it earns more.

### B5. Personal tilt / override file

`data/tilt.csv`: player, delta (or multiplier), note, date. Applied after the composite, always
rendered on the board as a distinct badge showing the size and direction, never silently folded
into the value. Marc is in the room and knows things the model doesn't; the tool should take
that as input rather than make him argue with the screen.

### B6. The amended composite

Once B3 and B4 produce challenge signals, wire them into `rejected`. Ship the rejection rule
only when a violation it acts on can be shown in real cached data. Until then the composite is
plain equal weight, and the UI says so.

### B7. Agent scouting

Two read-only sweeps, judged on merit before anything ships:

1. A genuinely new **independent, free, no-auth** projection source. Caveat up front: a 4th
   *correlated* source adds much less than the first three did, and `CLAUDE.md` already warns
   that ESPN and the Clay PDF are one source, not two.
2. **Other ways to challenge a projection.** Methods with a computable gate on data we already
   have cached, not opinions.

**Agents never produce projection numbers.** A number an agent invents looks exactly like one it
computed, and nothing downstream would catch it. Agents build validators, fetch sources, and run
harnesses. Every number entering the board comes from a source adapter or a fitted model, and
passes the existing gates.

## Backtest: verify before promising

Weighting sources by measured accuracy needs **2025 preseason** projections per source. Our
FantasyPros CSVs are 2026; Sleeper serves current-year only. If 2025 projections are not
retrievable, we cannot measure who was more accurate, and equal weighting is the correct
answer, because it is what you use with no track record to justify anything else. Check first,
claim second.

## Gates (unchanged, and they apply to all of the above)

1. Scoring reconciliation within 1.0 pt on ~12 players.
2. Crosswalk completeness: zero unresolved inside the top 200 by ADP.
3. Sanity invariants: `tools/run_invariants.py` PASS.
4. `pytest -q` all green; `cd frontend && npm run build` clean.

Every source board must pass the invariants **independently**. A FantasyPros-only board has no
per-player games figure and leans entirely on the availability prior, so it is the one most
likely to trip an invariant. That is a finding to report, not a check to relax.

## Decisions taken during the build (2026-08-20)

**Source selection is resumed from the event log.** `source_changed` was originally appended
and never read back, so a relaunch mid-draft reverted to the default board while the header
still showed a toggle. That is the exact scenario the append-only log exists for, and an event
written but never replayed also breaks the rule that state is a pure function of
(snapshot, events). `create_app` now reads the last `source_changed` and rebuilds that board.
The POOL still cannot be replayed (it comes from cached projections, not events); the
SELECTION can, and is.

Three sub-decisions, each with a test:

- An explicitly injected `pool` always wins, so tests stay hermetic and never depend on cached
  projection data.
- The resume runs BEFORE the default pool loads, so a resumed draft builds one board instead of
  building the default and discarding it. (A test asserting the default loader is never called
  is what caught the wasteful ordering.)
- A resume that cannot rebuild its board falls back **loudly**: warning logged, `active_source`
  left at the default, so the header never claims a source whose values failed to load.

**`team_name_candidates` in the state payload** is an addition beyond the original contract: the
ten seeded names, exposed so the draft-night naming panel does not carry a second hardcoded copy.
Kept.

**Bulk `/api/team-names` applies slots in sorted order**, so the resulting event sequence is
deterministic. The contract did not specify ordering.

**`LeagueConfig` gained `team_names`**, parsed from `league_manual.yaml` rather than hardcoded in
Python, per the "read the yaml, don't paraphrase it" rule in CLAUDE.md.

## Marc's decisions, round 2 (2026-08-20)

### The amended composite is a REVIEW QUEUE, not a rejection rule

Marc: *"I'd like to have outliers brought to me and highlighted and then we make decisions
around whether to boot it or not."*

This supersedes plan B6. Nothing is ever rejected automatically. The pipeline **surfaces
candidates**; Marc adjudicates; his decisions persist and feed `blend_statlines(rejected=...)`.

Why this is the right shape, beyond it being what he asked for: the scouting sweep found that
distance-based rejection is not statistically sound at three sources (the smallest well-defined
symmetric trim of three forecasts is just the median, and Stock & Watson 2004 measured a
"drop the worst source" screening rule doing *worse* than plain averaging in three of six
cases). A human deciding case by case has none of that problem, because no rule is being fit.
It also matches the repo's tone contract: the engine informs, never insists.

**Review happens at PREP time, never on draft night.** Draft night is the wrong moment to
adjudicate a projection, and the draft phase is read-only over a frozen snapshot by design.

The loop:

1. **Detect** candidates from two independent families, both of which only ever *flag*:
   - *Contamination* -- a failed accounting identity (team-envelope violation, B3), a bad
     crosswalk join, a unit error, or a constant masquerading as a projection (Sleeper's
     `games` = 18.0 for all 3,111 records, verified 2026-08-20).
   - *Distance* -- one source far from the other two on a stat (existing
     `valuation/disagreement.py`), plus the TD-regression flag (B4).
2. **Present** every candidate in one HTML review page: the player, the stat, each source's
   number, why it was flagged, and the board impact if rejected. Per-row choice of keep or
   reject-this-source-for-this-stat. Exports JSON.
3. **Persist** the decisions to `data/projection_decisions.json`, with the reason and date, in
   the spirit of `data/overrides.csv` (checked first, permanent, auditable).
4. **Apply** them as the `rejected` set the composite already accepts, and render every applied
   decision on the board as a visible badge. Never silently folded in.

Rejection is per **(source, stat, player)**, not per player: a source is usually wrong about one
thing (a receiver's targets) while fine on everything else.

### FantasySharks: add it

Free, no auth, 583 offensive players. Two reasons it is worth more than a fourth vote:

- **Targets.** `rec_tgt` is currently ESPN-only, so the composite cannot average it and the
  envelope validator cannot cross-check it. Going 1 -> 2 sources on a stat is a different
  move from going 3 -> 4 on an average.
- **Projected counts of games clearing each yardage threshold** -- exactly the quantity
  `valuation/bonuses.py` models, which currently has **no external reference of any kind**. The
  receiving thresholds match this league's 100/150/200 schedule exactly.

Hard constraints carried from the scouting sweep: the `Segment` id changes yearly and must be
read from the page's own `<select>`, never hardcoded; `Position=4` is WR, not 3; and independence
must be **verified before it enters any variance or disagreement measure**, because CLAUDE.md's
ESPN-and-Clay lesson (411/411 identical, one source counted as two) is exactly the mistake a
fourth source invites.

### Rejected: NFL.com

Its fantasy API returns 200 but ignores `season=2026` and serves 2025 data, and its own payload
states ESPN is now the official NFL fantasy game. It is the ESPN/Clay same-source trap wearing a
different hostname.

### Retired: the `top_qb_top8` invariant

Replaced by `check_top_qb_rank_shifts_with_qb_demand`. The `8` was never derived. Measured on the
real board, the QB curve's one dominant cliff is immediately after **QB1** (40.9 pts under the
composite; the largest gap on the entire board under all four sources, range 32.4-45.7), with QB1
at overall #9 and QB2 at overall #22 -- so rank 8 sat in empty space inside a 13-slot chasm.
Worse, the check's verdict tracked the active source rather than the model (QB1 lands #7 Sleeper,
#8 ESPN, #9 blend, #12 FantasyPros). The replacement tests the mechanism actually claimed: the
top QB must rank strictly better under this league's QB rules than under 1-QB rules (#9 vs #18 on
the real board). It also FAILS rather than passing vacuously if ever run on a 1-QB league.

## VERDICT: no renormalization (2026-08-20)

Marc challenged the accounting-identity finding directly: *"isn't the goal to most accurately
project each individual player... it's really discounting teams with multiple weapons."* Three
agents were run — one arguing for the correction, one against, one empirical arbiter with orders
to settle it by measurement rather than argument. **Both independent analyses reached the same
verdict: keep the identity as a review-queue hygiene flag, ship no remedy.**

### Why the remedy fails

**It does not beat a dumb null.** One-sided renormalization (fix overages only) genuinely improves
2025 error: blend MAE 37.14 -> 36.04, WR 35.87 -> 33.53, both p=0.000. But a **flat haircut
removing exactly the same league-wide total from exactly the same players, ignoring the identity
entirely**, gets 36.42. Identity versus its own null: p=0.128 overall, and on the top 60 by ADP
**the flat cut is ahead**. All 24 identity-vs-null comparisons came back "not distinguishable."
The whole gain is a level correction on a board already measured as 8-48 points hot; none of it
comes from the team-specific information the identity check exists to find.

**Ordering does not improve, which is the only thing a board consumes.** Spearman over the 449
players moved 0.7777 -> 0.7765 — very slightly worse.

**The literal two-sided proposal is worse than doing nothing** (37.14 -> 37.35; +4.9 pts/player on
the top 60). On 2025 a third of teams had receiving *below* their own passing, so a symmetric rule
scales those receivers UP by as much as +58%.

### Marc was right, and the mechanism is now measured

- **Projections are not expectations.** ESPN puts **89.9%** of drafted players at exactly 17.0
  projected games; they averaged **13.7**. Among players who actually played 15-17 games Sleeper's
  bias is **negative** 9.5 and 57.8% of them beat their projection. They are conditional-on-role,
  if-healthy scenarios, exactly as he argued, with the availability discount applied elsewhere.
- **The guilty side is the PASSING side, not receiving.** Netting each side against **rushing**
  (outside the identity, so shared optimism cancels): Sleeper pass/rush **1.048** vs rec/rush
  1.020. ESPN's ordering is the reverse, and per team it is a coin flip. Renormalization treats
  the passing side as the trustworthy budget, and on Sleeper it is the more inflated one.
- **The mechanism is missing quarterbacks.** Real 2025 top-passer share of team passing yards:
  mean **80.2%**, 13 of 32 teams below 80%. Every source projects the starter at 89-92%, the
  median outcome, because nobody publishes the backup who inevitably plays. Grossing QB rooms to
  the real mean flips the blend's median gap from +5.5% to **-7.7%** and violations from 29/32
  to 4/32.
- **The `+0.56` crowding correlation has an equal and opposite twin.** corr(gap, published
  catchers) = +0.56; corr(gap, published **passers**) = **-0.56**. Sleeper's headline TB +21.9%
  is a team where it published exactly ONE quarterback.
- **The metric moved on a publication convention.** Sleeper's 2025 file projected CIN 7,102
  passing yards (two full starters); its 2026 file has no such team. Year over year its passing
  side fell 8.9% while receiving fell 1.4%.

### Corrections to earlier claims in this document

- **"ESPN: 0 violations of 96" is a 2026 property, not a habit.** ESPN **2025** ran a median
  -0.17% with a range of **-37.6% to +97.6%** (Cleveland: 310 projected pass attempts against a
  league median of 561). Any reading of ESPN as the disciplined source is unsupported.
- The identity finding was overstated in this document as the strongest result available. It is
  real arithmetic, but its actionable content is a level effect that a blind haircut captures
  equally well, and it is heavily contaminated by how many quarterbacks a source chooses to list.

### What survives

- The identity stays a **hygiene flag in the review queue**, which is all
  `PROJECTION_CHALLENGES.md` ever claimed for it.
- **The honest per-team flag is PASSER COUNT, not catcher count.** Sleeper's overage runs a median
  +18.7% on teams with fewer than 2 projected passers versus +5.9% elsewhere.
- Re-run `tools/check_renormalization.py` beside `tools/backtest_sources.py` each January.

### The durable rule this established

**Every proposed correction must beat a dumb null of equal magnitude before it ships.** Not
"is it significant against doing nothing" but "is it significant against the crudest possible
intervention of the same size." Two candidates have now been declined on exactly this basis: the
per-position calibration shrink (`SOURCE_BACKTEST.md`) and identity renormalization. Neither
cleared its null. This is the general form of Marc's own objection to arbitrary thresholds, and
nothing in this repo has cleared that bar yet.
